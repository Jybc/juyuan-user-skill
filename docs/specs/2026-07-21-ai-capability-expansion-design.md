## 一、概述

本次扩展在聚源百成大师现有能力（选品、上架、订单、评价、退款、标题优化、SEO诊断）之上，新增两条产品线：

| 产品线 | 定位 | 核心功能 |
|--------|------|---------|
| **商品优化线** | 让每件商品卖得更好 | #3 季节选品日历 → #9 属性自动补全 → #6 详情页文案 |
| **利润经营中枢** | 盘活所有店铺数据 | #35 利润分析 + #33 自然语言问答 |

协同逻辑：优化线创造 GMV 增量，经营中枢提供决策可见性；两者互取数据，形成「看得见 → 改得好 → 卖得多 → 算得清」的闭环。

---

## 二、交互设计总原则

不再让用户在终端输入 `y/n` 或 `是/否`。所有交互使用 WorkBuddy 原生的富交互工具：

| 工具 | 用途 | 避免 |
|------|------|------|
| `AskUserQuestion` + 选项列表 | 让用户从预定义动作中选，带描述说明 | 不再用 open-ended 文本输入做决策 |
| `gen_apple.py` → `present_files` 展示 | 数据可视化：图表、卡片、对比视图 | 不吐原始 JSON 或纯文本表格 |
| SubAgent 逐项确认 | 批量操作中逐项审核，采纳/跳���/修正 | 不一键全部执行，给用户控制权 |

## 三、#3 季节性选品日历

### 3.1 产品定位

给鞋靴卖家的「什么时候该上什么货」决策辅助。基于历史销售数据 + 热搜词趋势，提前 30 天推送备货建议。

### 3.2 输入

```
┌──────────────────────┬──────────────────────────┬────────────────────┐
│ 数据源               │ 获取方式                  │ 示例               │
├──────────────────────┼──────────────────────────┼────────────────────┤
│ 6个月订单数据        │ trade-list API (已有)     │ 各品类月销量/均价   │
│ 当前在售商品         │ product-list API (已有)   │ 品类分布、库存状态  │
│ 热搜词库             │ shoe-hot-keywords.json    │ 795个鞋靴热搜词    │
│ 系统日期             │ 当前时间                  │ 判断季节窗口       │
└──────────────────────┴──────────────────────────┴────────────────────┘
```

### 3.3 输出

生成一份交互式 HTML 报告，通过 `gen_apple.py` 展示。页面包含：

```
┌─ 选品日历 → 未来30天 ────────────────────────────┐
│                                                    │
│  [品类趋势图]  凉鞋 ▼   单鞋 →   短靴 ▲   马丁靴 ▲▲│
│  (横向柱状图，红/绿箭头标注趋势方向)                 │
│                                                    │
│  ═══ 重点关注 ═══════════════════════════════════ │
│  ★ 短靴 — 热度快速爬升，历史同月销量42双           │
│    推荐热搜词: 方头短靴女、粗跟短靴、马丁靴女秋冬   │
│    选品建议: K3搜索「短靴」已有200+新款             │
│    [去K3选品] [添加到待发列表]                      │
│                                                    │
│  ★ 马丁靴 — 搜索热度开始抬头                       │
│    推荐热搜词: 马丁靴女秋、系带马丁靴、厚底马丁靴    │
│    建议: 先上3-5个款测试市场反应                    │
│    [去K3选品]                                       │
│                                                    │
│  ═══ 其他品类 ═══════════════════════════════════ │
│  凉鞋 → 热度下降中，建议清仓                        │
│  单鞋 → 稳定，正常节奏                              │
│                                                    │
│  [查看未来90天] [只看到店有货的品类]                  │
└───────────────────────────────────────────────────┘
```

### 3.4 交互流程

1. 用户说「选品日历」「该上什么秋款了」→ 触发
2. 选择平台：`AskUserQuestion` → `k3` / `bao66`
3. 选择预测周期：`AskUserQuestion` → `未来7天` / `未来30天` / `未来90天`
4. 驱动拉取 trade-list + product-list 数据
5. LLM 分析品类趋势 + 匹配热搜词，生成结构化数据
6. `gen_apple.py` 渲染 HTML 报告
7. `present_files` 展示
8. 每款推荐后面跟行动按钮：`[去K3选品]` — 触发搜索跳转；`[加到待发列表]` — 标记为待处理

### 3.5 趋势算法

```
品类热度分 = 热搜词指数(30%) + 自身销量趋势(40%) + 时间窗口 (30%)
  - 热搜词指数: 该品类关键词在词库中的搜索量权重
  - 自身销量趋势: 近30天 vs 前30天的销量变化率
  - 时间窗口: 根据系统日期 + 该品类历史销售曲线判断是否处于起量窗口
```

数据精度说明：使用了热搜词库的静态热度而非淘宝实时大盘数据，精度约 70-80%，足够指导中小卖家的选品决策。

## 四、#9 属性自动补全

### 4.1 产品定位

极速发布时卖家通常只填了标题和主图，属性字段大量缺失。这个功能根据标题语义 + 图片分析自动推断缺失属性，提升搜索完整度。

### 4.2 输入

```
┌──────────────────────┬────────────────────────┬──────────────────────┐
│ 数据源               │ 获取方式                │ 示例                 │
├──────────────────────┼────────────────────────┼──────────────────────┤
│ 商品标题             │ product-detail (已有)   │ 「一字扣凉鞋女厚底」  │
│ 商品图片URL          │ product-detail → 下载   │ 多模态(k2/m3/5v-turbo) │
│ 已有属性段           │ product-detail props    │ 可能为空的字段       │
�� 类目ID               │ product-detail cid      │ 50012025=女凉鞋      │
│ 类目属性枚举         │ 淘宝类目属性API(动态查询) │ 跟型/鞋头/材质/风格等  │
└──────────────────────┴────────────────────────┴──────────────────────┘
```

### 4.3 属性提取 LLM 逻辑

```
输入标题: "一字扣凉鞋女2026夏季厚底露趾仙女风"
         ↓ 分词 + 类目属性映射
  "一字扣" → 闭合方式: 一字式扣带  (高置信度)
  "凉鞋女" → 品类词确定
  "厚底"   → 跟型: 松糕底       (高置信度)
  "露趾"   → 鞋头款式: 露趾     (高置信度)
  "仙女风" → 风格: 仙女风       (中置信度)
         ↓ 图片验证 (多模态)
  主图中脚趾可见 → 露趾 ✓
  暖色调 + 花卉背景 → 仙女风 ✓
         ↓ 输出
```

```

### 4.5 交互流程

**入口**：用户说「检查属性」「属性补全」「全店属性巡检」
**单件模式**：发布时自动触发，先补全再发布
**批量模式**：

1. 用户说「全店属性巡检」
2. 拉取 product-list 全部商品
3. 逐件调 product-detail，提取标题+cid+已有属性
4. SubAgent 逐件推理缺失属性值 + 置信度
5. LLM 生成 HTML 对比表
6. `present_files` 展示
7. 每行后面操作按钮 → 通过 SubAgent 逐项确认，用户可选：
   - `AskUserQuestion`：`header: "属性 {n}/{total}"`，选项 `采用` / `修正`（自由输入）/ `跳过`
   - 或使用底部批量按钮一次性处理高置信度项

### 4.6 置信度处理规则

| 置信度 | 颜色 | 处理 |
|--------|------|------|
| ≥ 90% | 绿色 | 默认采纳，可手动修正 |
| 70-89% | 黄色 | 默认采纳，建议确认 |
| < 70% | 红色 | 不自动采纳，需手动选择 |

### 4.7 类目属性获取（动态查询）

不再维护静态 JSON 字典，改为通过淘宝类目属性 API 动态查询每个 cid 下的合法属性和属性值。例如��

- `taobao.itemcats.get` — 获取子类目列表
- `taobao.itemprops.get` — 根据 cid 获取该类目下的属性和属性值

每次属性补全时，根据 `product-detail` 返回的 `cid` 实时拉取对应的属性枚举，确保属性字典始终与淘宝最新类目体系同步。该数据按类目缓存 24 小时，减少重复请求。

  订单的 num_iid → 在数据库中查找该商品来源于哪次极速发布
  → 找到对应的 K3/Bao66 原始价格 → 作为拿货价

  降级策略:
  如果找不到发布记录（商品不是通过聚源百成大师发的）→ 提示卖家手动输入该商品拿货价
```

### 6.5 交互流程

**首次使用**：

1. 用户说「利润分析」「算算利润」「赚了多少钱」
2. 检测是否有包装/杂费配置
3. 没有 → `AskUserQuestion` 引导填写：

```
header: "成本配置"
question: "每单平均包装费和杂费大约多少？"
options: [
  { label: "¥2", description: "纸箱+胶带+气泡膜" },
  { label: "¥3", description: "品牌定制包装盒" },
  { label: "¥5", description: "礼盒+手提袋+贴纸" },
  { label: "自定义", description: "手动输入金额" }
]
```

4. 同时询问广告费：`AskUserQuestion` → `自动计算(仅成本+平台) / 含广告费(手动填写月总额)`
5. 拉取订单 + 退款数据 + 匹配拿货价
6. 计算 → `gen_apple.py` 渲染利润看板
7. `present_files` 展示

**后续使用**：记住配置，直接展示看板。

### 7.3 回答格式

每个回答包含三部分：**数据卡片 + 一句话解读 + 推荐追问**

```
用户: 最近生意怎么样？

聚源百成大师:
┌─ 本周经营快照 ─────────────────────────────────────┐
│                                                     │
│   成交金额         成交笔数       退货率              │
│  ¥12,800          127笔          5.2%              │
│   ↓ 8%             ↓ 12%          ↑ 1.1%           │
│                                                     │
│  ⚠ 凉鞋销量转淡（-15%），单鞋开始起量（+22%）。       │
│  有 3 笔待发货订单，1 笔退货待处理。                   │
│                                                     │
│  建议：凉鞋挂清仓促销，多上几款秋款单鞋。               │
│                                                     │
│  推荐追问：                                          │
│  [「凉鞋为什么不卖了？」] [「单鞋具体哪些款好卖？」]     │
│  [「看看利润分析」] [「帮我推荐秋款单鞋」]            │
└─────────────────────────────────────────────────────┘
```

### 7.4 交互流程

1. 用户在 WorkBuddy 中自然说一句话
2. LLM 意图识别（12 种意图类型）
3. 按意图拉取对应数据
4. LLM 解读数据 + 生成回答 + 推荐追问
5. 回答以格式化 Markdown（非 HTML）返回，嵌入基本信息卡片
6. 如果用户点推荐追问，自动进入对应功能流程

### 7.5 意图识别的容错

```
用户输入模糊时:
  "店铺怎么样了" → 默认返回经营概览
  "凉鞋"           → 追问: "你是想看凉鞋的销量/退货/利润/还是标题优化？"
                   → AskUserQuestion 4选1

用户输入跨意图时:
  "凉鞋卖得怎么样，要不要降价" → 识别为 [品类下钻 + 诊断建议]
  → 先拉凉鞋数据，再跑利润分析，最后给建议
```

## 十、已确认设计决策

1. **包装/广告费等手动输入项** — 首次使用时通过 `AskUserQuestion` 引导填写（选项化：¥2/¥3/¥5/自定义），后续自动记忆。
2. **属性字典来源** — 不维护静态文件，改用淘宝 `taobao.itemprops.get` API 动态查询，按 cid 缓存 24 小时。始终与淘宝最新类目体系同步。
3. **多模态图片分析** — WorkBuddy 环境确认支持（kimi-26 / m3 / 5v-turbo），用于 #6 场景识别和 #9 属性交叉验证。
4. **拿货价追溯** — 通过聚源百成大师极速发布的产品可追溯到 K3/Bao66 拿货价。手工上架的商品利润无法自动计算，系统会提示卖家手动输入该品拿货价。
